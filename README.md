## 先把账算清楚：你的直播吃多少上行、多少流量

带宽这件事很容易被“我家是千兆宽带”误导。家用宽带上下行不对称，下行能跑满标称值，上行经常只有 10–30Mbps；晚高峰家人一起刷视频，留给你的上行还会再缩水。直播间里那种“画面像 PPT 一帧一帧跳”的现象，八成就是上行被压到 5Mbps 以下。

TikTok Live Studio 官方文档写的最低上传带宽是 2.5Mbps 以上。这个数字仅代表能跑通，不代表能看。你按 2.5M 推 1080P，画面会直接变成马赛克。业内通行的实战分档是这样的：

| 直播方式 | 最低上行 | 推荐上行 | 典型场景 |
| --- | --- | --- | --- |
| 手机直播（720P） | 5Mbps | 5–10Mbps | 单人出镜、轻度带货 |
| OBS 推流（1080P/30fps） | 10Mbps | 10–20Mbps | 电脑直播、电商带货 |
| OBS 推流（1080P/60fps） | 15Mbps | 20Mbps 以上 | 高清才艺、动态画面 |
| 多账号矩阵 | 按账号数叠加 | 每账号独立带宽 | 矩阵带货、长时间挂播 |

推荐值之所以要留一倍以上余量，是因为码率并不匀速。画面一变复杂，瞬时码率能冲到平均值的 1.5–2 倍，带宽没有缓冲就会丢包，丢包就卡。有人把 20Mbps 当作 1080P 的及格线，这属于保守派口径，比 10–20Mbps 的主流建议留了更多冗余，预算宽裕可以照着来，预算紧就卡在 15Mbps 上下。

再看流量，这是最容易被误判的一项。1080P 每小时大约消耗 500MB，720P 大约 350MB。一天播 4 小时、一个月播 25 天，纯推流约 50GB；把回看、互动、养号刷视频都算上，一个月 100–200GB 比较稳妥，重度带货 500GB–1TB 也不夸张。

把这两个数字放在一起看，结论就出来了：**对单机直播来说，流量几乎不构成瓶颈，带宽和 IP 才是。** 一台给 6000GB 月流量的机器，按 1080P 每小时 500MB 折算能推一万两千小时，而一个月满打满算也才 720 小时。所以选套餐时先看带宽、CPU 内存和 IP 属性，再回头扫一眼流量够不够；被流量大小带着走，容易花冤枉钱。

## 卡顿和标黄的真正原因，多半不在设备上

直播卡顿的源头通常有四个，前三个都指向网络。

**上行不够**排在第一位。下行 100M 上行只有 5M 的家庭宽带，一开播就会出问题，这是最常见的隐形问题。

**延迟和丢包**排第二。官方建议 RTT 控制在 200ms 以内，理想值是 150ms 以内；丢包率官方容忍 2% 以下，但想要体验顺滑，实际得压到 0.5% 以内。普通中转线路跳数多，晚高峰一拥堵，画面就开始跳帧。

**IP 不干净**排第三，也是 TikTok 独有的一道审核。平台校验出口 IP 会看三个维度：注册地归属是否与账号注册地、常用登录地一致；ASN 归属是数据中心机房段还是真实家庭宽带；这个 IP 历史上有没有被标记过。三项里任何一项出问题，带宽再大也可能限流甚至 0 播放。很多人换了三四条线路还是被标黄，问题就出在 IP 本身，不在带宽。

**设备过载**排第四，也最好解决。CPU 长期跑到 90% 以上、OBS 弹出“编码过载”，降分辨率或换硬件编码就能缓和。

标黄这个现象值得单独说清楚。**标黄不等于限流，更不等于封号**，它是平台推流质量监测系统给出的降权警告：当系统检测到推流码率波动大、网络抖动超标或 IP 环境异常，会把你的直播间从高清推流池里移除，画面就发黄、发糊。经验口径上，单纯标黄推荐流还在，3–7 天可以改善；掉到限流（推荐流几乎归零、在线只有个位数）通常要 7–14 天；封号则是另一回事，只能申诉或换号。

处置顺序在运营圈里已经比较统一，属于经验做法，并非平台公开规则：先停播 24–48 小时，别硬播加深标签，期间正常刷视频、点赞、评论；再发 1–2 条不挂商品的短视频，把内容推荐权重洗回来；复播时前 10 分钟只互动不卖货，不提外链、不引导跳平台；最后一步是换干净的网络环境。前三步做得再认真，第四步不解决，基本等于白做。

## 普通宽带、机场、共享 VPS 为什么撑不起推流

刷视频是下行加载，容忍延迟；直播推流是上行传输，对抖动零容忍。这两件事对网络的要求差一个量级。

普通 VPN 走公共中转节点，节点拥挤时延迟飙到 300ms 以上很常见，出口 IP 几乎都是被反复使用的机房段，TikTok 一识别就限流。共享 VPS 便宜，但带宽是几十人共抢，隔壁跑个爬虫你这边就卡，IP 同样是机房段。跨境专线（IEPL、IPLC、IXP 这一类）解决的是另外三件事：带宽独享或可控、路由不绕公网、出口 IP 归属真实。晚高峰被标黄，多数情况是线路抖动导致丢包，并非绝对带宽不够，这也是为什么单纯加钱升带宽经常没用。

真正要盯的硬指标只有三个：IP 纯净度（原生 IP、归属当地主流 ISP、非机房段）、上行带宽（单人坐姿带货 ≥5Mbps，多机位走播 ≥10–20Mbps）、延迟稳定性（不看某一刻的 Ping 值，看 15 分钟持续推流的码率曲线平不平）。厂商常把“能解锁 Netflix、Disney+”当作 IP 质量的旁证，逻辑是这类 IP 没被标记成机房段，在 TikTok 的风控体系里同样更可信，这属于厂商说法，当参考即可。

选地区的第一原则是出口 IP 归属地与账号注册地、目标市场一致。新加坡节点天然对口东南亚市场；如果你做的是美区号，硬用新加坡出口，IP 注册地和账号归属对不上，反而给自己添风险。

## 买完不是万事大吉：OBS 端七个必调参数

网络只是基础，推流端参数不对，好线路照样卡。

1. **OBS 以管理员身份运行**。否则 Windows 给的资源调度优先级不够，编码容易掉。
2. **编码器优先 NVENC（N 卡）或 AMF（A 卡）**，软编 x264 吃 CPU，老机器直接过载。
3. **码率别一味拉高**。1080P/30fps 推 4000–6000 Kbps 足够，超过 8000 Kbps 收益递减还更容易丢包。
4. **关键帧间隔设 2 秒**，TikTok 官方推荐值。
5. **音频采样率 48kHz，码率 128–160 Kbps**。用 44.1kHz 容易出现音画不同步。
6. **打开“网络绑定优化”和“动态码率”**，网络抖动时自动降码率保流畅，比硬撑高码率卡死强。
7. **开播前测一遍**。Speedtest 测上传、Ping 测延迟和丢包。上行低于目标码率的两倍，别开播，开了也是卡。

## 常见问题

**5M 的线到底能不能播？** 能，但要限定条件：单台手机、720P 常规画质、没有其他设备抢带宽。这里说的 5M 是稳定可用的带宽，不是测速偶尔跳到 5Mbps。多机位、多人连麦、还要传文件，5M 立刻不够。

**为什么手机 5M 就够，电脑要 10M 起？** 手机通过 App 直播时，平台和手机会根据实时网络做一定程度的画质码率适配；电脑用 LIVE Studio 或 OBS 推流，分辨率、帧率、码率、编码器都是你自己设的，设到 1080P 就按 1080P 的码率走，网络不给够就直接掉帧。

**1080P 究竟要多少？** 主流口径 10–20Mbps，30fps 取中段，60fps 或画面变化剧烈往上加。保守派建议直接给到 20Mbps 以上。给不准的时候宁可多留，码率峰值是平均值的 1.5–2 倍。

**晚高峰就卡，是带宽不够还是线路问题？** 多数是线路抖动导致丢包，不是绝对带宽不足。判断方法：同时段测上传速度，如果速度没掉但画面在跳，就是丢包。加带宽解决不了，得换路由。

**一条线能带几个直播号？** 建议一个。同一出口 IP 登录多个直播号，容易被判定为矩阵操控，导致关联限流。

**换 IP 能解决标黄吗？** 看原因。IP 不干净导致的，换原生 IP 有明显帮助；设备性能或账号行为导致的，换 IP 只能暂时缓解。排查顺序是先网络、再设备、最后账号行为。

**推流码从哪来？** 只能从官方渠道：调用官方开播接口创建直播间，或通过 App、直播伴侣手动开播后获取。
